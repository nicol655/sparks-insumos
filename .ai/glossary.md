# Glossary

Domain terms as the storefront uses them. Spanish is the default locale (`es-AR`).

- **Familia olfativa** — grouping of a fragrance by its dominant character (floral, amaderada, oriental, fresca, gourmand, …). Travels as a slug in the API and URL (`?family=`); the label is translated in the dictionary. Home tiles and catalog chips are the same list from `getFacets()`.
- **Pirámide olfativa** — the three layers of notes on the product page: salida (top), corazón (heart), fondo (base). Rendered by `olfactive-pyramid.tsx`.
- **Concentración** — how much perfume oil the juice carries (EDP, extrait, …). Travels as a slug; the label is translated. Shown in the spec table, not as a catalog facet in Fase 1.
- **Packshot** — the hero still of the bottle. Product gallery is 4:5 plus three 1:1 thumbs (`gallery.tsx`). Cards use the same asset via `packshot.tsx`. Until real photos exist, a diagonal placeholder from §05 stands in; `srcset` 400/800/1200/1600 is already wired.
- **Nota** — a single smell listed on the pyramid or used as a search suggestion chip.
- **Facet** — a filterable dimension of the catalog (family, brand, size) plus its result count. Price is a range, not a chip.
- **Chip** — rounded-pill control (`--radius-chip`). Toggle filters use `aria-pressed`; a combination that would empty the grid becomes a 40% `span`, not a link (RF-2).
- **Overlay** — the single UI slot for cart drawer, search, mobile menu, or filter drawer. Opening one closes the other (`useUiStore`).
- **Canvas / ink** — the two ground colors of the system: warm bone (`#F5F1EA`) and near-black (`#14100E`). Gold (`accent-gold`) is an accent, not body text.
- **Sparks Insumos** — legal / storefront name on [sparksinsumos.com](https://sparksinsumos.com/). CUIT `20-95827720-3`. The new UI brand is **Sparks Parfums**; same business.
- **Sparks Mayorista** — how the live home and Quiénes Somos address the buyer (revendedoras y negocios). Minimum order and volume discounts apply to this motion.
- **Insumo** — a unit sold for resale (perfume, make-up, skincare, accessory), not a finished retail experience. Makeup ships in **tonos surtidos**.
- **Inspiración / réplica 1:1** — live-catalog labels for fragrances that evoke a designer scent. Not the designer’s own juice. Do not drop the qualifier in copy.
- **Mínimo de compra** — checkout floor **$30.000 ARS** excluding shipping (Tiendanube cart rule and home). Quiénes Somos still says $50.000; that page is stale relative to the cart.
- **Descuento por volumen** — automatic 5% from $100.000 and 10% from $300.000 on merchandise subtotal. One of three discount instruments. Does not stack with the club rate or a coupon until a written rule says so.
- **Sparks Club / socio** — customer tier with a permanent 5% off, pre-sales and a welcome coupon. The backoffice label is Club. Opposite of **Invitado**.
- **Invitado** — registered customer without the permanent 5%. Can still buy.
- **Botón de arrepentimiento** — Argentine cooling-off control. Live destination: `/contacto/?order_cancellation_without_id=true` on sparksinsumos.com.
- **Defensa del consumidor** — live link to the national form: `https://www.argentina.gob.ar/produccion/defensadelconsumidor/formulario`.
- **Franklin** — published address / showroom (CABA). Pickup and “retiro” copy refer here, not Palermo.
- **Via Cargo** — the second shipper next to Correo Argentino. Buyer pays; quote by size and weight.
- **Cuenta** — a buyer registered on `api/` (spec 007). Identified by email and password. Storefront pages `/ingresar`, `/registro` and `/cuenta` are live ([008](specs/008-cuenta-storefront/spec.md)). `/me` is the API resource, not a page path. A cuenta is not an operator.
- **Backoffice** — internal Next.js app in `backoffice/`, container `sparks-backoffice`. Design source is the artifact `NtzZJG94zfZrj3LpMvAtS9` only. Built today: login, the shell, resumen and ajustes as static copy ([011](specs/011-backoffice-cascaron/spec.md)), Catálogo list plus create and edit ([014](specs/014-catalogo-backoffice/spec.md), [016](specs/016-edicion-producto/spec.md)), and Usuarios: client list, create drawer and edit drawer, with the Equipo tab empty ([019](specs/019-usuarios-backoffice/spec.md)). Session in Zustand + `sessionStorage` ([ADR-0014](decisions/0014-sesion-backoffice-session-storage.md)). Pedidos, mensajes, cupones and contenido are still title only.
- **Equipo** — backoffice operators, invited separately from customers. Seeded API roles: **`admin`**, **`sales`**, **`customer`**. Grants are rows in `role_permissions` over a migration-owned permission catalog. Panel entry needs `backoffice_access`. Role/permission UI is out of scope until a later panel slice ([020](specs/020-roles-permissions/spec.md), [ADR-0027](decisions/0027-rbac-catalogo-y-denegacion-opaca.md)).
- **Role** — one required FK per user (`users.role_id`). Slug identifies the seed row (`admin`, `sales`, `customer`). Soft-deleting a role that still has users is 409.
- **Permission** — catalog row: `controller` + optional `method` (null for method-less grants such as `backoffice_access`). Controllers are not created at runtime; operators only check/uncheck methods on a role via `PUT /roles/{id}/permissions`.
- **`deleted_at`** — soft-delete timestamp on users, roles, permissions, products, categories, and tags. Lists and retrieve exclude non-null rows; soft-deleted ids look like unknown (404). Soft-deleted users cannot log in. Product soft delete does not purge S3 objects ([ADR-0028](decisions/0028-soft-delete-deleted-at.md)).
- **Pedido** — an order. Statuses: pago pendiente, preparando, enviado, entregado, cancelado. Payment: tarjeta, transferencia or efectivo. Enviado and entregado carry a tracking code.
- **Stock bajo** — 1 to 3 units on hand. **Agotado** is 0. Both surface on the resumen and the product row.
- **Cupón** — a code the team creates: percent or fixed ARS, optional use cap (0 = none), expiry, everyone or club-only, active or paused. Codes drawn in the prototype are fixtures, not live codes.
- **Mensaje** — a contact-form item in the backoffice inbox. Status nuevo or respondido. Reply in the panel or via WhatsApp.
- **Destacados** — up to 4 published products pinned on the home. The content screen enforces the cap.
- **Body splash** — a catalog category in the backoffice, next to Perfume and Set. Not a storefront facet in Fase 1.
- **Ajustes** — the settings screen that owns store name, contact, pickup, minimum, dispatch window, carriers, volume tiers, club rate, payment toggles, languages and currency. Defaults are in `business-model.md`.
- **`active`** — user row flag for operator block without delete. `false` blocks login; the row stays and the email stays unique. Soft delete is `deleted_at`, not this flag.
- **`must_change_password`** — user row flag. Login still issues a session, but every other authenticated call returns 403 `password_change_required` until `POST /auth/change-password`. The bootstrap user is created with this flag set.
- **Audit** — append-only row of an action a later spec marks with the `audited` decorator ([012](specs/012-auditoria/spec.md)). Stores `user_id`, `action`, optional resource table name, optional JSON payload, and `created_at`. Not every request is audited. The password is not part of the payload. Read with `GET /audits` and `GET /audits/{id}` after the password change. Account routes do not write a row. Product, category and tag CRUD do ([013](specs/013-productos/spec.md)).
- **Product (API)** — a row in `products` ([013](specs/013-productos/spec.md)): cost, sell price, `digital` or `physical`, visibility, S3 photo keys, one category, many tags. Not the storefront `Product` in `web/src/lib/api/contract.ts` (that one still has family, notes, stock and integer ARS, and still comes from fixtures).
