# Spec a feature

Create or refine the specification for the feature described after the command.

1. Load context first (`.ai/project.md`, `constitution.md`, relevant `specs/`).
2. Create `.ai/specs/<NNN-slug>/spec.md` from `.ai/specs/TEMPLATE/spec.md`
   (next free number). If refining, edit the existing one.
3. Capture: problem, user stories with priorities, functional & non-functional
   requirements, and testable acceptance criteria.
4. Resolve ambiguity by asking the user — do not invent requirements. List any
   open questions explicitly and stop for answers if they block the spec.
5. Keep it about the *what/why*, not the *how* (that's `/plan`).

End by summarizing the spec and asking for approval before `/plan`.
